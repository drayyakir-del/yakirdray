## ✨ What this project demonstrates

| Area | Highlights |
|------|-----------|
| **Semantic HTML** | Accessible landmark structure, RTL (`dir="rtl"`) layout, meaningful headings, no `<div>` soup |
| **CSS Architecture** | 12 focused stylesheets split by concern, ordered as an intentional cascade — base, layout, components, motion, responsive |
| **Vanilla JavaScript** | ~3,200 lines across 7 self-contained modules, namespaced, no jQuery, no bundler |
| **Accessibility (a11y)** | Custom preferences widget compliant with **WCAG** and Israeli Standard **IS 5568 / Regulation 35**: contrast modes, text scaling, line-height, motion reduction, big cursor — persisted to `localStorage` and applied **before first paint** to avoid FOUC |
| **SEO** | Open Graph, Twitter Cards, and **Schema.org `LocalBusiness`** structured data for rich search results |
| **Performance** | No render-blocking frameworks, font preconnect, progressive enhancement — content stays visible with JS disabled |
| **Forms & UX** | Client-side validation with Hebrew error messaging, screen-reader announcements via `role="alert"`, WhatsApp submission flow |

## 🧱 Architecture

```
yakirdray/
├── index.html            # Main landing page (semantic, RTL, SEO-tagged)
├── accessibility.html    # Accessibility statement (legal compliance)
├── css/                  # Modular stylesheets, loaded in cascade order
│   ├── base.css          #   design tokens, resets, typography
│   ├── layout.css        #   page grid & structure
│   ├── buttons.css  cards.css  content.css  forms.css  faq.css
│   ├── hero.css     floating.css
│   ├── a11y.css          #   accessibility preference styles
│   ├── responsive.css    #   breakpoints
│   └── motion.css        #   animations & prefers-reduced-motion
├── js/                   # Vanilla JS modules (namespaced under YD)
│   ├── core.js           #   shared utilities & namespace
│   ├── a11y-widget.js    #   accessibility preferences engine
│   ├── contact-form.js   #   validation + WhatsApp submission
│   ├── navigation.js  reveal.js  faq.js  misc.js
└── photo/  favicon.png  braindray.png
```

**Design principles applied here:**
- **Separation of concerns** — styles split by responsibility, JS by feature.
- **Progressive enhancement** — the page is fully readable and usable without JavaScript; JS only *enhances*.
- **No black boxes** — every line is authored and understood, not generated by a framework.

## ♿ Accessibility — a first-class concern

The accessibility widget (`js/a11y-widget.js`) is a genuine engineering feature, not a plugin:

- Toggles CSS classes on `<html>` only — never mutates page content or injects ARIA.
- Preferences (contrast, text size, line height, reduced motion, big cursor, link/heading highlighting) are saved to `localStorage` and **re-applied before the first paint**, so a returning user never sees a flash of the default theme.
- Built to satisfy **IS 5568 / Regulation 35** and **WCAG** guidance.

## 🚀 Run it locally

No build step, no `npm install`.

```bash
git clone https://github.com/drayyakir-del/yakirdray.git
cd yakirdray
```

Then open `index.html` in a browser, or serve it statically:

```bash
python -m http.server 8000
# → http://localhost:8000
```
